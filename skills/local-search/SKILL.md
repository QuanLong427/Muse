## 本地搜索 Skill

使用 `local_search` 工具搜索本地曲库：

- 参数：`query`（搜索关键词）、`limit`（返回数量，默认 20）
- 返回 JSON: { "total": number, "tracks": [{ "id", "title", "author", "url", "bvid", ... }] }

**不要使用 bash + curl 调用本地搜索 API**，直接使用 `local_search` 工具。

### 搜索规则

- API 对 title、author、filename 做模糊匹配，关键词命中任一字段即返回
- 曲库中部分曲目 author 字段为空，歌手名可能只出现在 title 或 filename 中，这很正常
- 只要搜索返回了结果（total > 0），就说明命中了，应将这些结果推荐给用户
- 可多次调用，使用不同关键词缩小范围
- 搜索返回结果后直接推荐，不需要额外检查 API 是否正常
- 用户说"推荐几首歌"等模糊请求时，可使用空关键词 q= 获取全部曲库，再从中挑选
- 从结果中选择要展示的真实歌曲后，调用 `present_tracks(track_ids=[...])`；只能传入本轮 `local_search` 返回的精确 `id` 或 BVID
- `present_tracks` 会由后端生成结构化 Track 卡片；不要在回答中重新输出 JSON 或伪造 Track
- 对搜索结果的自然语言说明必须保留原始标题含义，不得声称未返回的版本、歌手或可用状态

### 简繁体中文搜索策略（重要）

- 曲库文件名可能混合使用简体和繁体中文，搜索 API 只做精确字符匹配
- **先判断关键词是否包含简繁不同的字符**：如果关键词本身简繁体写法完全相同（如"大地恩情"、"雨天"、"花"），只需搜索一次
- **只有简繁体写法不同时**（如"张学友"vs"張學友"、"听海"vs"聽海"），才发起简体和繁体两次搜索
- 将搜索结果合并去重后推荐给用户
- 如果两次搜索 total 都为 0，才告知用户本地曲库未找到

### 自动切换云端

当本地搜索返回 total=0 时，**自动切换到云端搜索 Skill** 并告知用户。

“推荐几首”“类似音乐”“适合当前场景”等推荐意图不适用本节，必须加载
`music-recommendation` Skill，由其统一处理画像、LLM-Wiki、本地/云端配额和降级。

### 播放流程规则（最高优先级）

当用户说"播放XXX"、"我想听XXX"、"来一首XXX"时：
1. **必须先调用 local_search 搜索本地曲库**
2. 本地有结果（total > 0）→ 直接使用返回的本地 Track，严禁调用 convert_video 或 bili_search
3. 本地无结果（total = 0）→ 切换到云端搜索 Skill
4. **只有用户明确说"云端/B站搜索"时，才跳过本地搜索**

**禁止行为：**
- 本地有结果时仍调用 convert_video
- 未调用 local_search 就直接调用 bili_search 或 convert_video
