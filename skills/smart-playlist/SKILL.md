# 智能歌单

智能歌单负责把用户的场景与约束转换为本地 Track 与联网待下载候选。使用
`create_smart_playlist`；不要用多次 `local_search` 后由模型自行拼凑歌单。

## 意图区分

- “推荐几首歌”属于 `music-recommendation`，结果只读，不创建播放会话或歌单。
- “播放《某首歌》”属于精确本地搜索和播放器工具。
- “为夜跑生成 30 分钟歌单”“按我的偏好组一个歌单”属于本 Skill。

## 参数和默认值

- 保留用户明确指定的场景、数量、时长、歌手、流派、语言、情绪、版本排除和能量曲线。
- 用户未指定数量和时长时，使用 `count=3`。
- 多个歌手或版本通过逗号分隔传入。
- 默认 `source_policy="balanced"`，本地与联网约各 50%，候选不足时动态调整；用户明确要求离线时使用 `local`，仅联网时使用 `cloud`。
- 创建请求只授权生成草稿，不授权保存或下载。点击草稿确认按钮，或在后续对话明确确认这份草稿，才授权下载其中的联网候选；成功后加入同一歌单并后台同步 LLM-Wiki。
- `Live`、翻唱、Remix、伴奏等排除只根据可观察标题/文件名执行，不能猜测版本。

## 动作边界

1. “生成、创建、保存一个智能歌单”和“给歌单加入10首”都先用 `create_smart_playlist(action="preview")` 生成草稿；不能在同一创建请求中自行确认。兼容的 `action="save"` 也只产生草稿。
2. 用户明确要求立即播放或替换当前播放内容时，使用 `action="play"`。成功后必须等待浏览器 ACK，不能把指令下发描述为播放成功。
3. 用户明确说“就这样，确认添加”“确认保存这份”时，读取当前草稿的 ID 和 revision，使用 `manage_playlist_draft(action="confirm", draft_id=..., expected_revision=...)`。多个未保存草稿时必须明确选择，不按最新消息猜测。报告真实保存结果、本地新增数量和下载任务状态，不声称全部下载完成。保存不修改播放内容。
4. 预览返回 `warnings` 或 `status="needs_confirmation"` 时，说明未满足或无法核验的约束，并停在预览；不得声称已经播放或保存。
5. 只有用户看到警告后仍明确接受这些限制，才可用相同约束重试并设置 `accept_warnings=true`。
6. 含联网歌曲的预览不能直接完整播放；`needs_download` 要说明先添加歌单下载，完成后播放命名歌单。不得只播放本地部分却声称完整播放成功。

## 为已有歌单补歌

- 从当前会话已确认的结果或 `list_music_playlists` 取得目标 ID；有多个可能目标时澄清，不按名称猜测 ID。
- 使用 `create_smart_playlist(target_playlist_id=..., count=..., action="preview")`，生成绑定原歌单的追加草稿；确认后才批量添加和下载。`count` 是本次新增数量，不是最终总数；“补足到10首”先扣除已有数量。
- 预览与应用必须保留相同 `target_playlist_id`；服务排除已有 Track，校验所有权和 revision，重复应用同一批次不会重复添加或重复下载。
- 不使用 `save_current`（保存当前播放内容为新歌单）或 `recommend_next`（补充 Radio 播放内容）替代补歌；这些操作的目标不是命名歌单。
- 本地不足时由服务调整来源比例；候选仍不足则说明缺口，不重复搜索同一组结果或擅自放宽用户约束。
- 保存成功只代表本地部分已加入、联网部分已建任务。报告实际新增数量、待下载数量和未满足条件，不声称请求数量已全部可播放。

## 调整同一份草稿

- 用 `manage_playlist_draft` 的 `list/read` 获取数据库实时状态；使用精确 `draft_id`、`expected_revision` 和 `item_ids`。
- Agent 工具的 `item_ids`、`exclude_versions` 使用 JSON 编码字符串数组，例如 `item_ids="[\"条目ID\"]"`；服务与 HTTP 接口内部仍使用原生列表。参数错误或 revision 冲突表示未完成修改，不能声称已删歌或已换歌。
- “换掉第三首”“保留前五首”“不要现场版”分别映射为 `replace`、`remove`、`filter_versions`；排序用 `reorder`，改名用 `rename`，补歌用 `add`。不重新生成整份草稿。
- 替换/追加可以指定已搜索到的本地 `track_id`，或审计批次 `candidate_batch_id` 和 `candidate_track_id`；没有指定歌曲时服务在原约束下选新候选。候选不足就说明缺口，不擅自放宽约束。
- 草稿修改不下载、不保存命名歌单；取消草稿不删除本地音频。已确认草稿不可编辑；确认失败重试也必须提交原冻结版本。

## 展示与解释

- 草稿卡片由后端结构化结果自动输出，不再用 `present_tracks` 把歌单拆为单曲卡片，也不要在回答里伪造歌单 JSON。
- 推荐理由只引用返回的 `reasons`、当前场景和真实偏好证据。
- `duration_is_estimated=true` 时必须明确说时长为估算值。
- 情绪、语言或能量曲线缺少元数据时，只能说明未做强过滤，不能宣称约束已经满足。

## 不变量

- 审计批次不可变；可编辑草稿引用当前选择的审计快照并有独立版本。旧版本不能确认，不修改 PlaybackSession 或命名歌单。
- 播放只替换 PlaybackSession，并保留一次撤销入口；不修改来源命名歌单。
- 保存使用精确预览，原子创建歌单并写入本地 Track，联网候选进入持久后台任务；下载成功且取得真实 Track 后才能加入歌单。重复保存同一批次不会重复创建；失败重试仍关联原歌单，已删除歌单不得自动重建。
- 负向反馈和可结构化的长期回避项必须先过滤，不能只降低分数。
