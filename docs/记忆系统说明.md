# Musicer 记忆系统说明（v2.2）

> 状态：当前实现
> 总体架构：[项目架构说明](./项目架构说明.md)
> 后续需求：[需求文档](./需求文档.md)

## 目标与边界

记忆系统用于维持对话连续性和保存可靠的用户偏好，但不会把每条消息都当作长期事实。它将原始证据、候选判断和生效指令分开，并与 LLM-Wiki 的音乐领域知识保持独立。

## 分层

1. **工作上下文**：服务端从当前会话加载最近 16 条 user/agent 消息。浏览器只传 `user_id` 和 `session_id`，不是历史事实源。
2. **原始事件流**：SQLite 完整保存消息、工具调用和工具结果，并记录用户、会话、场景、时间与元数据。它是证据，不直接作为 prompt 中的情景记忆。
3. **事件记忆（episode）**：每轮结束后，把可观察事实整理为目标、上下文、约束、动作、结果和实体引用，并保留原始消息 ID。失败和协议阻断的轮次也会保存为审计证据，但不会进入成功经验召回。不会保存模型隐藏思维链。
4. **候选记忆**：Dream 只从用户消息提取结构化候选，每个候选保留来源消息 ID、置信度和证据类型。
5. **长期记忆**：只有通过确定性门槛的候选成为 active 指令。高置信度强制约束与当前请求相关的当前场景/全局指令会注入 Agent 系统上下文。
6. **领域知识**：音乐事实进入 LLM-Wiki。网页内容和 Wiki 结果不会自动变成用户偏好。

## 存储

`memory/data/memory.db` 包含：

- `memory_users`：用户。
- `memory_sessions`：会话、场景和逻辑清除位置。
- `memory_messages`：可追溯的原始交互事件。
- `memory_episodes`：轮次级事件记忆，包含 `goal`、`context`、`constraints`、`action_summary`、`result_status`、`result_summary`、来源消息 ID 和歌曲/歌单等实体引用。
- `memory_candidates`：Dream 候选、证据和审核状态。
- `memory_items`：已经生效或被遗忘的长期记忆。
- `memory_dream_runs`：Dream 运行记录。

`memory/data/playlist.db` 属于当前播放会话，`memory/data/music-library.db` 属于命名歌单与播放事件，两者都不属于用户记忆。播放事件是近期偏好计算的事实来源，但不会直接晋升为长期记忆。旧 `history.jsonl` 只迁移一次，迁移记录标记为已处理。

Markdown 仅用于检查，不是主要事实源：`memory/data/user_profile.md` 只保存全局画像和全局结构化记忆；各场景投影拆分到 `memory/data/scenarios/<安全名称>-<摘要>.md`。非默认用户位于 `memory/data/users/<user-hash>/` 下的同构目录。旧 `user_profile.md` 中的 `## 场景:*` 会在初始化时无损迁移，Agent 每轮只读取全局文件与当前场景文件，不会把其他场景一起放入上下文。

## 写入与晋升

- 用户明确表达偏好或纠正，且置信度不低于 `0.75`：可晋升。
- 重复行为推断，置信度不低于 `0.85`：还需要独立证据。
- 临时请求、Agent 自行推断和外部内容：拒绝成为长期偏好。
- 来源消息 ID 不存在或由模型虚构：拒绝。
- Dream 只有在解析和候选落库全部成功后，才把该批消息标记为已处理。

Dream 可由后台定时器运行，也会在待处理消息达到阈值时由聊天链路触发。显式 `remember_preference` 只用于用户明确要求“记住”；`forget_preference` 只在用户明确要求删除/纠正时软删除。

## 读取与上下文关系

每轮 ReAct 当前使用三种记忆：

- 自动注入：高置信度的全局交互/语言/回避约束确定性加载；其余当前场景和全局长期记忆按当前请求的关键词、场景、置信度与更新时间排序，合计最多 6 条。推荐、歌单和场景化请求会保留更多个性化偏好。
- 自动条件注入：只有个性化、多步骤、纠正、推荐/歌单/搜索/下载等值得回忆的意图才检索 episode，相关度达标时注入最多 3 条。简单控制、能力说明和概念解释不查询 episode 存储。
- 按需检索：模型在上述上下文仍不足时调用 `search_memory`，查证可追溯的历史原文。

episode 当前使用中文二元词、关键词覆盖、场景、时间衰减、重要度、置信度和结果状态混合排序，只召回 `success` 或 `partial` 记录，`failed` 记录仅供审计。它已支持无需“我之前说过”的隐式召回，但还不是向量语义检索，同义表达仍可能漏召回。`search_memory` 使用 SQL `LIKE`，用于精确历史查证。

每个新 episode 的 `context.retrieved_episode_ids` 会保存本轮实际引用过的旧 episode，后续可用于解释“为什么这样推荐/操作”。播放器客户端动作只有收到 ACK 才能记录为成功；真实开始、暂停、播完、跳过与反馈由独立播放事件表保存。

## HTTP 与 Agent 入口

- `GET /api/history`：会话历史。
- `GET /api/memory`：结构化长期记忆。
- `GET /api/memory/episodes`：查看或检索 episode。
- `GET /api/memory/search`：历史消息搜索。
- `DELETE /api/memory/items/{memory_key}`：软删除长期记忆。
- `POST /api/dream`：手动触发 Dream。
- Agent 工具：`search_memory`、`remember_preference`、`forget_preference`。
